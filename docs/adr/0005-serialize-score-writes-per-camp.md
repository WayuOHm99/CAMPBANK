# Serialize Score writes with a Camp row lock

Every Score-writing RPC locks the Camp row before its Group row, serializing Score changes within one Camp; lifecycle and Budget writes use the same Camp lock, so a concurrent Close or Score action is decided solely by which transaction obtains the lock first. This trades unnecessary write parallelism for a simple, auditable guarantee that shared Budget cannot be overspent; the expected 5–10 concurrent Staff make the trade-off appropriate, and it should be revisited only if Camp write volume grows substantially. Every Score write, activation, and close checks that distributed Score equals the sum of Group Scores. If the check fails, the Camp stops accepting Score actions and surfaces a critical Admin error rather than repairing either value automatically.
