# Use Supabase anonymous identities for Camp access sessions

Browser devices authenticate through Supabase Anonymous Auth and receive an `access_sessions` record scoped to a Camp, member, and access surface; an Admin session is granted only after a restricted PostgreSQL RPC verifies the PIN hash with `pgcrypto` and atomically applies attempt throttling and lockout. Staff device preferences contain no authority, and rotating a Staff Join Code revokes the affected sessions. Login success, failure, lockout, PIN reset, and session revocation are audited without storing PINs or request bodies. We chose this over routing normal traffic through a Next.js backend with the Service Role so RLS and filtered Realtime remain the primary security boundary, while the Service Role is reserved for server-only bootstrap and recovery.
